# MSAL App Registration for v0.8

One-time tenant-admin task: register an Entra (formerly Azure AD) app so the load-test tool can use MSAL.js for in-browser silent token refresh. Once this is done, individual users no longer have to run `Update_Token_Only.ps1` every 60 minutes.

## What you're registering

A **Single-Page Application (SPA)** that:
- Signs in real users (delegated permissions, not application permissions)
- Requests Power BI service scopes
- Uses the page's origin as redirect URI (so works from `file://` and `http://localhost`)

## Steps

### 1. Create the app registration

In the Entra admin center:

1. **Microsoft Entra ID** → **App registrations** → **+ New registration**.
2. **Name:** something descriptive, e.g. `RealisticLoadTest-Tool`.
3. **Supported account types:** "Accounts in this organizational directory only" (single tenant).
4. **Redirect URI:**
   - Platform: **Single-page application (SPA)**
   - URI: leave blank for now; add multiple in step 3.
5. Click **Register**.

After creation, note these two values:
- **Application (client) ID** — paste into `auth-config.json` → `clientId`.
- **Directory (tenant) ID** — paste into `auth-config.json` → `tenantId`.

### 2. Add API permissions (delegated, Power BI)

In the new app:

1. **API permissions** → **+ Add a permission** → **Power BI Service**.
2. **Delegated permissions** (NOT application).
3. Tick:
   - `Report.Read.All` — required to embed any report.
   - `Workspace.Read.All` — required for the in-page Setup picker (lists workspaces/reports). Skip only if you exclusively use pre-configured `PBIReport.json` files generated by `Setup_Load_Test.ps1`.
   - `Dataset.Read.All` — optional; reserved for v1.0 features.
4. Click **Add permissions**.
5. Click **Grant admin consent for <tenant>** (requires Global Admin or Privileged Role Admin).

> **Already had an app reg without `Workspace.Read.All`?** Add it now (steps 3–5 above) and update `auth-config.json` `scopes` to include `https://analysis.windows.net/powerbi/api/Workspace.Read.All`. The next sign-in will prompt for the new consent automatically.

### 3. Configure SPA redirect URIs

In the new app:

1. **Authentication** → under **Single-page application** click **Add URI** for each location the page will be opened from. Add at minimum:
   - `http://localhost` (covers any local port)
   - The exact `file://` URL won't work — Entra rejects `file://` redirect URIs. Workaround: serve the HTML from a local web server. v1.0 will provide a built-in coordinator for this; for v0.8 either:
     - Run `python -m http.server 8080` from the test folder and open `http://localhost:8080/RealisticLoadTest.html`, **OR**
     - Open the HTML in Edge with the `--disable-web-security` flag (NOT recommended for production tenants).
2. Under **Implicit grant and hybrid flows**: leave both checkboxes **unchecked** (we're using auth-code+PKCE, the modern flow).
3. **Allow public client flows:** No.
4. Click **Save**.

### 4. Populate `auth-config.json`

Copy the example file:

```powershell
cd RealisticLoadTestTool
cp auth-config.example.json auth-config.json
```

Edit `auth-config.json`:

```json
{
  "clientId": "<paste Application (client) ID>",
  "tenantId": "<paste Directory (tenant) ID>",
  "scopes": ["https://analysis.windows.net/powerbi/api/Report.Read.All"]
}
```

`auth-config.json` is in `.gitignore` — never commit it.

### 5. Smoke test

1. Serve the test folder over HTTP: `python -m http.server 8080`.
2. Open `http://localhost:8080/RealisticLoadTest.html`.
3. **First visit:** the page shows a "Sign in with Microsoft" button (no auto-popup — browsers block those). Click it. A popup opens requesting your Microsoft sign-in.
4. After sign-in, the embedded report should render.
5. **Subsequent visits:** the token is cached in `localStorage`; the page signs in silently with no button or popup, even after the original 60-minute token expires.

If sign-in fails:
- **AADSTS50011 (redirect URI mismatch):** the URL you opened the page from isn't in the SPA redirect URI list. Add it in step 3. Entra does exact-string matching including port — `http://localhost` will NOT match `http://localhost:8080`. Add the exact origin you serve from.
- **AADSTS65001 (consent required):** admin hasn't granted admin consent. Re-do step 2.5.
- **CORS / opaque popup error:** check the browser console; usually the SPA platform isn't configured (still set to "Web" — must be "Single-page application").
- **`popup_window_error: Error opening popup window`:** the browser blocked the auto-popup on page load. Modern browsers only allow popups triggered by a direct user click, but v0.8 fires `acquireTokenPopup` from the bootstrap flow with no click. **Workaround:** click the blocked-popup icon in the Chrome address bar (or `chrome://settings/content/siteDetails?site=http%3A%2F%2Flocalhost%3A8080`) → set Pop-ups to **Allow** → reload. After the first successful sign-in, the token is cached and subsequent reloads acquire silently with no popup. **Permanent fix tracked as backlog row T5a (explicit "Sign in" button).**

## Notes on scope choice

- Don't use `https://analysis.windows.net/powerbi/api/.default` for delegated flows — that's the application-permission scope and you'll get consent prompts.
- For "embed for your customers" / app-owns-data scenarios, you'd use a service principal (v2.0 plan) instead of MSAL in the page. v0.8 only handles "embed for your organization."

## Fallback if you can't register an app

**There is no fallback in v0.8.** The legacy `PBIToken.json` + `Update_Token_Only.ps1` path was removed (backlog T5b). If your tenant cannot register an Entra SPA app, you cannot use v0.8. Options:
- Stay on v0.7.1 until your tenant policy changes.
- Wait for v1.0, which replaces CefSharp with Playwright and may enable a service-principal-based path for tenants that block delegated app registration.
