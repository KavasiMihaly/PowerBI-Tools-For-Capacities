## Pre-requisites for running any test

Before any test in this plan can execute:

1. **Baseline captured** — `_Test/baselines/v0.7.1/` populated with at least one 30-min run on the demo `.pbix` and a summary at `_Test/baselines/v0.7.1-summary.md` containing avg / p50 / p95 refresh durations. (Backlog row TP3.)

3. **Demo `.pbix`** deployed to a Power BI workspace the test user has access to.
4. **Entra app registration** completed (one-time tenant admin task) for tests that exercise MSAL — see `_Documentation/MSAL-app-registration.md`.
5. **`auth-config.json`** populated locally (not committed) for the test machine.

## Tests

### TEST-V08-01: Clean-machine bootstrap (regression baseline first, then verify v0.8 fix)

**Verifies:** T1 — the rawgit CDN replacement actually works.

**Prerequisites:** Fresh Windows VM (no cached browser data). Chrome installed. Tool checked out from repo.

**Steps:**
1. **Pre-fix baseline:** On the fresh VM, check out the v0.7.1 tag. Open `RealisticLoadTest.html` directly. Open DevTools → Network. Reload.
2. Confirm the request to `cdn.rawgit.com/Microsoft/PowerBI-JavaScript/master/dist/powerbi.min.js` fails (404 / DNS error / CORS error). Take screenshot to `_Test/Printscreens/v0.8/TEST-V08-01-baseline-fail.png`.
3. **v0.8 fix:** Switch to v0.8 branch. Reload the page.
4. Confirm `lib/powerbi-client-2.23.x.min.js` loads from local file (200 from `file://` or vendored path). No external CDN request.

**Pass criteria:**
- Step 2 shows the rawgit request failing — proves the regression today.
- Step 4 shows the vendored file loading without internet access.
- Power BI report renders successfully on v0.8.

**Fail criteria:**
- v0.8 still requests a remote CDN that isn't a Microsoft-controlled domain.
- Vendored file loads but report fails to embed.

### TEST-V08-02: jQuery removal

**Verifies:** T2.

**Prerequisites:** v0.8 build.

**Steps:**
1. `grep -rn "jquery\|googleapis\|\\$\\.\\|\\$(" RealisticLoadTestTool/RealisticLoadTest.html`
2. Open `RealisticLoadTest.html` in Chrome with DevTools → Network → "JS" filter.
3. Verify no jQuery script is loaded.
4. In the DevTools console, run: `typeof jQuery`

**Pass criteria:**
- Step 1 returns no matches (or only matches inside JSON template literals that don't execute).
- Step 3 shows no `jquery*.js` request and no requests to `code.jquery.com` or `ajax.googleapis.com`.
- Step 4 returns `"undefined"`.

> **Footgun (do NOT chase the `$` symbol):** Chrome DevTools attaches its own `$` shortcut (`document.querySelector` alias) to the console scope, including via `window.$`. The function source shows `[Command Line API]` as a tag. Even `typeof window.$ === 'function'` proves nothing because of this. **Test `jQuery` only** — jQuery *always* defines both `jQuery` and `$` together, so `typeof jQuery === 'undefined'` is sufficient proof that jQuery is gone, regardless of whatever else may have set `$`.

**Fail criteria:**
- `typeof jQuery` returns `'function'` (jQuery is loaded).
- Network log shows a jQuery file or a request to `code.jquery.com` / `ajax.googleapis.com`.
- Source grep finds executable jQuery-style calls (not in JSON literals).

### TEST-V08-04: JSONL output schema validity

**Verifies:** B1 / T4.

**Prerequisites:** v0.8 build, demo .pbix, `numberOfViews=10`.

**Steps:**
1. Run the test to completion.
2. `cd "Test Results/<run>"`
3. `cat *.jsonl | jq . > /dev/null` (parse-check every line)
4. `jq -r '"\(.event)\t\(keys | sort | join(","))"' *.jsonl | sort -u`
5. `grep -l '<br>' *.jsonl`

**Pass criteria:**
- Step 3 exits 0 with no parse errors.
- Step 4 produces one line per distinct event type, with the keys for each event matching `_Documentation/JSONL-schema.md` "Expected key sets" table:
  - `loaded` → 13 base keys
  - `rendered` → 15 keys (base + `durationMs`, `isFirstRender`)
  - `error` → 15 keys (base + `errorCode`, `errorDetail`)
  - `view_limit_reached` → 13 base keys
  - `auth_failure` → 14 keys (base + `errorDetail`) (only if exercised)
- Step 5 returns no matches (no `<br>` characters anywhere).
- At least one `rendered` row has `isFirstRender: true` (cold-start flag fired) and at least one has `isFirstRender: false` (steady state).

**Fail criteria:**
- Any line fails JSON parse.
- Schema differs from documented schema in `_Documentation/JSONL-schema.md`.
- Any `<br>` tag appears.

### TEST-V08-06: MSAL silent token refresh during 8-hour run

**Verifies:** T5 — the killer feature of v0.8.

**Prerequisites:** Entra app registration completed. `auth-config.json` populated. Test machine clock correct. Set `numberOfViews` high enough that the test runs > 75 min (covers original 60-min token expiry).

**Steps:**
1. Open `RealisticLoadTest.html` in Chrome.
2. Sign in via MSAL popup.
3. Open DevTools → Application → Local Storage → look for `msal.account.keys`. Note the token's `expiresOn` timestamp.
4. Run for at least 75 minutes (or until 5 minutes past `expiresOn`).
5. After the original token would have expired, watch the test continue.
6. `cat Test Results/<run>/*.jsonl | jq 'select(.event=="error")'`

**Pass criteria:**
- All refreshes after the original 60-min mark complete successfully.
- No `auth_failure` or `token_expired` events in JSONL (step 6 returns nothing).
- `view.current` keeps incrementing past the 60-min mark.
- The browser console shows MSAL silently acquiring a new token at least once.

**Fail criteria:**
- Any error event with `auth` or `token` in `event.detail`.
- Refresh count flatlines around the 60-min mark.
- Browser console shows uncaught exception from `accessTokenProvider`.

### TEST-V08-10: Performance regression vs v0.7.1 baseline

**Verifies:** all of v0.8 — the upgrade shouldn't cost real-world performance.

**Prerequisites:**
- `_Test/baselines/v0.7.1/` populated (TP3 done).
- `_Test/baselines/v0.7.1-summary.md` documents avg / p50 / p95 / count.
- Same demo `.pbix`, same scenarios, same machine, ideally same time-of-day to minimize Power BI service variance.

**Steps:**
1. Run identical scenario on v0.8 build.
2. `jq '.durationMs.current' Test Results/<run>/*.jsonl | datamash mean 1 perc:50 1 perc:95 1` (or PowerShell equivalent if datamash unavailable).
3. Compare against `_Test/baselines/v0.7.1-summary.md`.

**Pass criteria:**
- Mean within ±5% of baseline.
- p95 within ±10% of baseline (allows some noise on slow renders).
- Refresh count over the same wall-clock duration is within ±5%.

**Fail criteria:**
- Any aggregate >10% worse than baseline → investigate before shipping; do not ship v0.8 on regressed performance.

### TEST-V08-11: Browser compatibility

**Verifies:** T1 + T3 + T5 work across browsers.

**Prerequisites:** v0.8 build. Chrome, Edge, Firefox installed.

**Steps:**
1. Run a 5-view test in Chrome. Capture JSONL.
2. Run the identical test in Edge. Capture JSONL.
3. Run the identical test in Firefox. Capture JSONL.
4. Compare row counts and aggregate metrics.

**Pass criteria:**
- All three browsers complete the test.
- All three produce JSONL of the same row count and matching schema.
- Mean refresh duration within ±15% across browsers (Firefox is typically slowest for embedded iframes).

**Fail criteria:**
- Any browser fails to load the page.
- Any browser fails MSAL signin.
