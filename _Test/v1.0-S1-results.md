## Defects / observations / future cleanup

**No defects.** Three observations for future stages:

1. **Cold-start time is dominated by manual sign-in click latency.** The first `rendered` event includes wall-clock from `runTime` init through the user's interaction with the MSAL popup. This is correctly captured by `isFirstRender: true` so analysis can split it out, but for headless / cached-token runs the cold-start number will be ~5–8 s (auth handshake + SDK init + iframe load) rather than 175 s. Worth measuring once we have Stage 2 dashboard.
2. **Browser profile is per-run** (`Test Results/<runId>/.browser-profile/`). Means every new `node run.js` invocation starts with no MSAL cache and requires interactive sign-in. Stage 2 or 3 should add a `--profile-dir <shared-path>` flag so headless runs can use a previously-warmed cache. Already mentioned in `runner/README.md` "Limitations" section.
3. **Concurrency 3 with 5 s launch spacing means the third window opens 10 s after the first.** That's deliberate (matches old PowerShell behavior — avoids initialization stampede), but for high-concurrency tests it's a long ramp. Consider exposing `--launch-spacing-sec 0` as a documented "all at once" mode in Stage 2 docs.
