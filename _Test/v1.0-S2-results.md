### TEST-V10-09 — Coordinator security: localhost-only by default ⏸ DEFERRED (non-blocking)

Code-review pass — `server.js` binds to `localhost` by default (`HOST = args.host || (DEV_MODE && args.bind === '0.0.0.0' ? '0.0.0.0' : 'localhost')`). The `--bind 0.0.0.0` flag *requires* `--dev` to take effect, so accidental LAN exposure isn't possible without two flags + reading the warning banner. LAN-from-second-machine test deferred to opportunistic verification when LAN access is convenient; not blocking ship.

## Defects / observations / future work

**No defects.** Three observations:

1. **Coordinator state is in-memory only.** Restart loses the live buffer. Disk JSONL files (written by the runner) are still canonical. If long-term aggregation across coordinator restarts becomes useful, Stage 4+ could add an optional `--persist-buffer` flag that writes a snapshot on SIGINT.
2. **Per-report rollup includes ALL coordinator-lifetime data, not just the current run.** That's intentional (cumulative cross-run comparison is useful) but might surprise users expecting "this run only" view. Future enhancement: a `/status?runId=...` filter.
3. **Setup picker bug discovered during testing:** the user ran with the in-page Setup picker selecting different reports per window, and the dashboard correctly aggregated 3 separate reports. Confirmed the picker remains usable in Stage 2 (no regression from Stage 1).

## Bug fixed during Stage 2 implementation

- **`/dashboard` returned 404.** First run after writing the coordinator. Cause: `serveStatic` looked for a literal file named `dashboard` (no extension). Fix: added explicit route handler for `/dashboard` in `handle()` before the static fallback. The `.html` extension fallback for arbitrary paths is deferred until Stage 5 introduces `/setup`.
