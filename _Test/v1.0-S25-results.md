## Summary

OneDayBI brand applied across all three existing HTML views. Single source of truth at `RealisticLoadTestTool/lib/onedaybi.css`; per-page CSS reduced to ~10–25 lines of view-specific overrides only. Brand tokens taken from the `brand-guidelines` skill (`brands/onedaybi.md`) — Microsoft-aligned digital palette (Primary Blue `#0078d4`, Accent Green `#10b981`, Dark `#111827`) — chosen over the marketing folder's print-oriented Navy/Amber palette because the surfaces are digital UI in a Power BI tool.

**B7 → Done.**

## Files added

- `RealisticLoadTestTool/lib/onedaybi.css` — single brand stylesheet. Defines tokens via CSS custom properties on `:root`; ships components (`.odbi-card`, `.odbi-stat`, `.odbi-btn`, `.odbi-banner`, `.odbi-badge`, `.odbi-table`, `.odbi-form-row`, `.odbi-header`, `.odbi-footer`, `.odbi-top-bar`, etc.). One file = one place for future palette tweaks.
- `RealisticLoadTestTool/lib/onedaybi-logo-dark.svg` — white-text variant for dark headers (dashboard, RealisticLoadTest). Copied from `OneDayBI Marketing/Design/onedaybi_logo_vector_white_text.svg` (6.4 KB true vector — the `_transparent.svg` variants were 2 MB rasterized SVGs, rejected as too heavy).
- `RealisticLoadTestTool/lib/onedaybi-logo-light.svg` — navy-text variant for light headers (UserGuide).

## What was deliberately NOT changed

- **No copy edits.** Existing technical text stays exactly as it was.
- **No accessibility audit.** Contrast ratios for the new palette look fine on inspection (white on `#111827` is WCAG AAA), but a formal a11y pass is its own backlog item.
- **No marketing-site additions.** Product UI only.
- **Setup wizard wireframe redesign.** Stage 5 builds `Setup.html` from scratch — it'll inherit `onedaybi.css` from day 1 (the whole point of doing 2.5 now).

## Known Stage 5 prep

The brand CSS includes `.odbi-form-row` styles (label + input/select with focus ring, disabled state) that match what the in-page Setup picker already uses. Stage 5's `Setup.html` will reuse the same class — no extra CSS work needed there.
