## Summary

Stage 4 replaces the v0.8 per-folder JSON config (`PBIReport.json` + `Filters.json` + `Bookmarks.json` + `Page.json`) with a single human-editable `loadtest.yaml`. The runner reads the manifest, expands into `concurrency × scenarios` browser tabs, and passes each scenario to `RealisticLoadTest.html` via a base64-encoded querystring. A migration script (`coordinator/migrate.js`) converts an existing v0.8 folder to YAML, preserving every legacy semantic — including the nested-array multi-select filter cycling.

Both Stage 4 acceptance tests pass on the data path. The metric-parity portion of V10-03 is deferred because the v0.7.1 baseline run (Backlog row TP3) is still `Pending User Run`; the round-trip itself is proven field-for-field in code.

**T9 → Done.**
